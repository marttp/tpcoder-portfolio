Model เก่งขึ้น Agent ทำงานได้มากขึ้น มันก็ดีสำหรับผมแหละครับ เดี๋ยวนี้ผมโยนงานที่ต้องแก้หลายไฟล์ให้มันทำได้ กลับมาก็มี diff ให้ดู แล้วผมมีเวลาไปคิดมากขึ้นว่าระบบควรทำงานยังไง ผมชอบทำงานแบบนี้นะ

ที่ผมคิดอยู่คือ พอ Agent มึนขึ้นมาจะเกิดอะไรขึ้น มันยังอธิบายสิ่งที่ทำได้แบบฟังขึ้น ทั้งที่แก้ผิดจุด ตอนนั้นเราต้องรอให้มันบอกว่าสิ่งที่ทำมาถูกแล้ว หรือเราเข้าใจงานพอที่จะตัดสินเอง?

![วิศวกรไล่ดูเส้นทางที่แตกออกเป็นเหตุการณ์ซ้ำ](/assets/images/blogs/when-your-ai-agent-gets-confused/trace.webp)

สมมติผมให้ Agent เพิ่ม retry ใน worker ที่ส่ง notification เทสต์ผ่าน diff ก็ดูโอเค แล้วถ้า provider รับ request แรกไปแล้ว แต่ฝั่งเรา timeout ก่อนเห็น response ล่ะ? พอ retry ผู้ใช้อาจได้แจ้งเตือนซ้ำ ก่อน approve ผมอยากรู้ว่าระบบกันแบบนี้ยังไง และเทสต์ที่ผ่านครอบคลุมเคสนี้หรือยัง ถ้าถาม Agent แล้วมันยังวนอยู่ที่เดิม ผมต้องไล่ flow ต่อเองได้

![วิศวกรตัดสินใจด้วยตัวเองที่โต๊ะทำงาน](/assets/images/blogs/when-your-ai-agent-gets-confused/decision.webp)

ผมยังให้ Agent ช่วยอ่าน log เสนอวิธีแก้ หรือเขียนเทสต์ของเคส timeout ได้ นี่แหละงานที่ผมอยากให้มันช่วย ส่วนจะเอาวิธีแก้นั้นขึ้น production ไหม ผมต้องตัดสินเอง เวลาเพื่อนในทีมถามว่าทำไมถึงแก้แบบนี้ ผมก็ควรอธิบายได้ และถ้าขึ้นไปแล้วมีปัญหา อย่างน้อยผมก็รู้ว่าจะเริ่มไล่จากตรงไหน

**พอผมเลือกส่งงานที่ Agent ทำออกไป งานนั้นก็เป็นผลงานของผมครับ** Agent เก่งขึ้น ผมก็รับงานได้มากขึ้น สิ่งที่ผมยังอยากทำได้คือรับผิดชอบงานที่ตัวเองส่ง แม้ในวันที่ Agent มึน
